Automation

The CLI and the MCP server

Every change is a typed command. The desktop app, the command-line tool and the MCP server run the same commands through the same engine. A batch applies completely or not at all, and undoes as one step.

Every example on this page was run against the 0.2.0 command-line tool; the outputs shown are what it printed. The files used live in the repository's fixtures, so run the commands from a checkout. processcraft-cli.exe is in the installer and in the portable ZIP.

Build a project from a batch

List every command, with the JSON Schema of the request protocol. Then build a project from a JSON batch and read back its document and diagram IDs.

processcraft-cli commands --json
processcraft-cli run --new Procurement --batch tests/fixtures/commands/procurement.json --out procurement.processcraft
processcraft-cli info procurement.processcraft

run prints a JSON receipt with "ok":true and the content identity of the saved project; info lists the documents, for example "id":"11111111-1111-4111-8111-111111111111" with the diagram procurement_diagram. To change an existing project, start from it with --in instead of --new; this batch adds a folder and a dictionary of roles and systems:

processcraft-cli run --in procurement.processcraft --batch tests/fixtures/commands/library-dictionary.json --out procurement-dictionary.processcraft

Read projections without changing the file: processcraft-cli query procurement-dictionary.processcraft dictionary (also documents, table, conventions, attributes, diagnostics and more; query --help lists them).

Validate against conventions

validate applies the profile stored in the project, or the one you pass with --profile. It exits with 3 when it finds an error, or a warning if you pass --fail-on warning, so it works as a CI gate. The summary line goes to stderr; the diagnostics go to stdout as JSON.

# project with a stored profile: 4 warnings, so this exits 3
processcraft-cli run --new Procurement --batch tests/fixtures/conventions/pass.json --out conventions.processcraft
processcraft-cli run --in conventions.processcraft --batch tests/fixtures/commands/raci.json --out project.processcraft
processcraft-cli validate project.processcraft --fail-on warning
# stderr: 0 error and 4 warning diagnostics
# the same project with the default threshold exits 0
processcraft-cli validate project.processcraft

To try a profile without storing it, write one and pass it. This one makes an implicit join an error:

# profile.json
{"rules": [
  {"type": "labelRequired", "severity": "warning", "kinds": ["Activity", "Event", "Lane", "Participant"]},
  {"type": "gatewayFlowsLabelled", "severity": "warning"},
  {"type": "noImplicitSplitJoin", "severity": "error"}
]}

processcraft-cli validate project.processcraft --profile profile.json
# stderr: 1 error and 0 warning diagnostics; exit code 3

In that output the finding is conventionImplicitJoin on the element end: "Element has several incoming flows; use a gateway to join." (two flows run into the one end event of the procurement process). The schema of a profile is the one of the setConventionsProfile command in commands --json.

RACI as JSON or CSV

processcraft-cli query project.processcraft raci 11111111-1111-4111-8111-111111111111 procurement
processcraft-cli export-raci project.processcraft 11111111-1111-4111-8111-111111111111 procurement --out raci.csv

The CSV is UTF-8 with a byte order mark and CRLF line ends. For this project it reads:

Activity,Finance manager,Procurement,Requester,Legal
Review request,C,A,R,I
Place order,I,"R,A",C,

The same table is on the features page. The output is byte-identical to tests/fixtures/commands/raci.expected.csv.

Images with an attribute overlay

Find the attribute's ID with query attributes, then export a PNG, SVG or PDF with the overlay. --overlay-mode is heatmap (the default) or badge; --dark renders the dark appearance and --scale sets the size.

processcraft-cli query project.processcraft attributes 44444444-4444-4444-8444-444444444444
processcraft-cli export-image project.processcraft --document-id 44444444-4444-4444-8444-444444444444 --diagram-id conv_diagram --format png --out cost-badges.png --overlay-attribute 44444444-4444-4444-8444-000000000010 --overlay-mode badge

The two figures on the features page were produced this way, from an onboarding process built from the batch recorded in tests/fixtures/prompts/text-to-model.transcript.json plus six Cost values.

BPMN in and out

processcraft-cli export-bpmn project.processcraft --document-id <document-id> --out diagram.bpmn --acknowledge-native-fields
processcraft-cli import-bpmn diagram.bpmn --out diagram.processcraft
processcraft-cli info diagram.bpmn

Without --acknowledge-native-fields, export-bpmn refuses when the project holds data BPMN cannot carry (navigation and dictionary links), and says what it would leave out. info on a BPMN file reports the import outcome before you create anything. export-drawio, layout-preview and layout-apply complete the set.

MCP for AI agents

The MCP server speaks JSON-RPC 2.0 over stdio, one message per line. It offers seven tools: inspect, validate, query, apply, save, export and reconcile. File access is limited to the folders you name. Nothing listens by default.

Standalone

# a new project; the agent may write only below C:\models\out
processcraft-cli mcp --new "Invoice approval" --write-root C:\models\out

# an existing file, read from one folder and saved to another
processcraft-cli mcp --in C:\models\procurement.processcraft --read-root C:\models --write-root C:\models\out

An MCP client sends these three lines to start; the server answers the first with its name and version and the third with the tool list (checked against 0.2.0):

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"test","version":"0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}

Most MCP clients take a command and arguments in their configuration; point them at processcraft-cli with the arguments above.

Attached to the desktop app

processcraft-cli mcp --attach <pipe> --token <token> --session <session id>

On Windows, the agent can edit the project that is open on your screen. You switch this on in the desktop app, which shows the pipe, token and session ID and asks you to authorize folders. This path was not run for this page, and the desktop side of it is one of the manual checks still open on the status page.

The prompt pack

The repository holds four instruction documents for an agent that drives this server: turn a written description into a model, review a model against the conventions, explain a process in plain language, and fill attributes from source material. They are plain text and also agent skills. The recorded runs behind them are replayed in the project's CI to check that the calls still work. How well any particular model follows the instructions has not been measured, and no claim is made about it.
