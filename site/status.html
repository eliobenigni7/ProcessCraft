Status

What is verified, and what is not

ProcessCraft 0.2.0 is pre-alpha. For trying it out and for modeling on Windows it works. It is not a finished product. This page follows the evidence files in the repository, which record what was run and what was measured. Last updated 14 November 2026; every change is in the changelog.

Since 0.2.0

Not in a release yet. These changes are to the website, the documentation and the project's own process; the app itself is unchanged since 0.2.0.

  • Documentation. A documentation book with three paths: analysts (install, a procurement tutorial, the canvas, attributes, conventions and RACI, files), developers (the CLI, batches, the file format, architecture) and AI agents (the MCP server and the prompt pack). Agents can read llms.txt, llms-full.txt or the Markdown copy of any page.
  • Generated reference. The pages listing every CLI subcommand and all 167 batch commands are generated from processcraft-cli, and CI fails if they no longer match it.
  • Contributing. A contributor guide, a security policy with private vulnerability reporting on GitHub, a code of conduct, a support page, issue forms for bugs, BPMN interchange problems and feature requests, and a pull request checklist.
  • Website. Redesigned in the app's own colours and fonts, around images of the app and its exports.

Verified

  • Quality gates. At the M5 qualification run: formatting, Clippy with warnings as errors, and the full test suite, which passed 1,258 tests with 0 failures and 3 ignored.
  • CLI workflow for the analyst layer. A repeatable script drives attributes, conventions, RACI, the overlay and a BPMN round trip through the command line only; all 10 checks pass. For example, the saved file reopens with the same content identity, and the RACI export matches a pinned CSV byte for byte.
  • Installer. For the 0.1.0 package, which shares the installer definition of 0.2.0, the per-user install, upgrade from a lower version, refusal of a downgrade, a failed install that rolls back, uninstall, and the wizard pages were run on one Windows 11 machine, and a per-machine install from an elevated shell.
  • Release. 0.2.0 was built by the release workflow and published with an MSI (56.5 MB) and a portable ZIP (66.5 MB).
  • Documentation. The book and the site were built and checked locally in light and dark appearance and at phone width, with no broken internal links; the published pages respond. CI on main passes with the reference check included.
  • Prompt pack. Two rounds of runs by fresh agent sessions led to changes in the documents. The documents were changed again after the second round and have not been re-run by a fresh agent since.

Measured

All numbers come from one machine (AMD Ryzen 5 5600X, 17 GB of memory, NVMe SSD, Windows 11), two release-build runs, 95th percentile of wall time. The model is the project's medium test fixture: 20 documents, 5,000 nodes, 500 shapes in the open diagram, a 20 MiB resource, and a 21.2 MB native file. The probe added 10 attribute definitions and 10,000 attribute values.

Not verified

M5's manual checks are still open, so M5 is released but not closed:

  • The procurement workflow with attributes, conventions, RACI and overlay in the desktop app, by hand, including save and reopen. The command-line half is done. The analyst tutorial follows the same workflow; its desktop steps were written from the app's controls and have not been run by hand either.
  • The same workflow through MCP attached to the open desktop app.
  • Opening the exported BPMN in an external tool (bpmn.io or Camunda Modeler), saving it unchanged and importing it again, to see whether pc:attributes survives. Nothing was observed, and no claim is made.

Also not established:

  • Signed builds. The packages are unsigned.
  • macOS and Linux. Only Windows is supported, and saving is qualified only on local NTFS.
  • Screen-reader support on the canvas, and keyboard-only use of every view. The installer wizard was driven by window messages, not by keyboard or Narrator.
  • Formal performance targets on very large models, and any machine other than the development PC.
  • Complete BPMN 2.0.2 coverage or OMG conformance. Coverage is a tracked, tested profile.
  • The quality of any AI model's output when it uses the prompt pack.

Roadmap

ProcessCraft stays offline, single-user and agent-ready. Real-time collaboration, cloud storage and accounts, ERP connectors, a process execution engine and a built-in AI provider are out of scope. The detailed plan is in the repository; these are plain-language summaries, not promises or dates.

M4: finish shipping (open)

  • Signing. Sign the installer and ZIP through a free open-source signing programme, and verify the signatures.
  • Installer follow-ups. Check the "Everyone" path with a real administrator prompt, cancelling mid-install, and machines other than the development PC.
  • Accessibility and performance. Keyboard-only modeling, table and dictionary workflows; Narrator; focus, contrast and display scaling; recorded timing and memory on a declared machine.

M5: analyst foundations (released, not closed)

Attributes, conventions, RACI, the overlay and the prompt pack are in 0.2.0. Closing M5 needs the manual checks listed above.

M6: publish and structure

Export a project as one self-contained HTML handbook with a process map, one page per activity and search that works from a file share, plus a PDF from the browser. A process map document with drill-down into sub-processes and called processes. A semantic diff between two versions, from the command line and as an overlay.

M7: analyse

A seeded simulation of a process from attributes, gateway probabilities and resources, with what-if comparison of two scenarios. It estimates behaviour and never runs a process. Visio import follows, but only once real sample files are available.

M8: decide

DMN decision tables linked to business rule tasks, with the same keep-or-refuse rule for DMN files as for BPMN.

M9: observe (optional)

Local event logs: import, conformance checking against a model, and a performance overlay; process discovery only later. Everything would stay on your machine.
