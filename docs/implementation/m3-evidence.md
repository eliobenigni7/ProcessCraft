Link source/target text and compensation activity references are checked as expanded QNames.

## Interop repair (post-M3, IO and CLI)

Import changes in `processcraft-io`, keeping the rule that content outside the qualified profile is preserved byte-for-byte or refused:

- Unprefixed DI `bpmnElement`/`sourceElement`/`targetElement` values resolve to local IDs whatever the default namespace (no default, BPMN MODEL default as Signavio/Bizagi write, or targetNamespace as bpmn.io writes). A prefixed value outside the targetNamespace is still refused.
- A `callActivity@calledElement` that names nothing in the file is no longer a structural import error; it is reported as an unresolved external QName. Editing such a file still needs the core reference rule changed (`activity_family_reference_issues` treats it as a missing local target), so it stays preserved source.
- Prefixed root attributes such as `modeler:executionPlatform` stay editable: the definitions default-namespace binding is no longer stored as context for foreign attributes, which are always prefixed.
- Collaboration-level text annotations, groups and associations are accepted as DI targets of a collaboration plane.
- Activity data associations without an `ioSpecification` pass the IO parser, but core validation (`data association requires activity ports`) still refuses them, so bpmn.io data associations remain preserved source.
- The preserved-source limitation names the reason, for example `Semantic editing disabled (extension attributes inside this element at <task id="task">); source retained byte-for-byte`.

Measured on 120 files (the 39 pinned `tests/fixtures/bpmn` fixtures plus 81 Camunda/bpmn.io/Signavio-style audit samples): 111 editable, 6 preserved source (four data-association cases, one dataInputAssociation without the required targetRef, one unresolved calledElement), 3 rejected (DTD, malformed, invalid UTF-8). `minimal.bpmn` is now editable through `prepare_import`, and its manifest expectation was updated (fixture bytes unchanged). A bpmn.io file that round-tripped byte-identically before still does after import and export.

CLI and MCP: `info` and `validate` detect the format from the content (ZIP or XML), not the file extension. For BPMN they report the real import outcome (`editable` or `preservedSource`), the diagram IDs and the reason; `validate` also checks the prepared import against core invariants. `info` on a project lists document IDs with their diagram IDs and prints `contentId` as hex. `import-bpmn --out *.bpmn` is refused. Native-only commands refuse BPMN XML input with a hint. Missing-path errors include the path. `export-image` checks the scale range first and names `--acknowledge-diagnostics`. All subcommands and flags have help text. The MCP `query` inputSchema declares `"type":"object"`, `serverInfo.name` is `processcraft`, and `save`/`export` check the write-root grant before testing whether the file exists. Gates on Windows 11: fmt, workspace Clippy with `-D warnings`, and `cargo test --workspace --all-targets --all-features --locked --offline --no-fail-fast` (1023 passed, 0 failed).

Deferred: missing BPMNLabel still hides names in the renderer (`processcraft-render` `label_visible`; an IO-only fix would add `<BPMNLabel/>` on export and break byte-stable round trips).
