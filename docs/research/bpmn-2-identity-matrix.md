# BPMN semantic and diagram identity/presence audit

The pinned `Semantic.xsd` declares `tBaseElement.id` and `tBaseElementWithMixedContent.id` optional. PDF §8.3.1 Table 8.5 requires an ID when the element is referenced or intended to be referenced and permits omission otherwise. `BPMN20.xsd:tDefinitions.id` is optional. `DI.xsd:DiagramElement.id` and `Diagram.id` are optional, as is `Diagram.name`. XSD reference attributes and their target rules are independent: a required reference needs an addressable target; it does not make every instance of its target class require an ID. Do not confuse internal editor identity, semantic XML ID and representation XML ID, or conflate a missing name with an explicit empty string.

This matrix covers currently modeled families, not all BPMN classes. P is bounded partial support, U means unverified for the full row, S means bounded preserved-source fallback. Columns are model, edit/create/delete, render/hit-test, import, export and validate. Required user interaction, all transports and native migration are not established by a partial cell. Type-specific names marked required in the pinned XSD remain required; no blanket optional-name rule is implied.

A systematic implementation needs stable internal handles independent of optional source XML identifiers and explicit presence for optional names. It must update command/reference resolution, semantic and DI selection, canonical digest, history, checkpoints, recovery, capability negotiation and schema migration together. On export, preserve original absence where permitted; require or allocate an XML identifier only through a deliberate, reviewable rule when a newly created reference requires one, and never silently change unrelated source identity. Old schema identity must be verified before migration. Test omitted versus explicitly empty names, anonymous unreferenced elements, required references, duplicate IDs, semantic/DI ID distinction, native save/reopen and BPMN export/reimport, undo/redo and protected-source fallback across each family. Do not claim support from a per-family boolean or successful XSD validation alone.
