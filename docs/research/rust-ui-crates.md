# Rust desktop UI crate research

Checked 2026-11-11. Scope: the existing native eframe/egui workbench, not a framework migration. The initial research below was followed by the requested integration and compatibility checks described in the next section.

## Integration result

`egui_extras = 0.37.0` and `egui_ltreeview = 0.10.0` are now exact desktop dependencies with default features disabled. Cargo added only these packages and `enum-map` / `enum-map-derive`. The three data views use `TableBuilder`; the project navigation uses `TreeView` with a guarded adapter for existing model IDs, keyboard input and named egui controls.

Both compile against the existing StoryTold egui commit `6d518fc799681571963842f95b55a6b68431b15a` without patching or vendoring either crate. `cargo tree -p processcraft -i egui --locked --offline` resolves one egui instance shared by both crates, eframe and the desktop. Locked offline build and interaction tests now replace the earlier version-only compatibility assessment. See [verification evidence](../implementation/ui-production-evidence.md).

`egui_ltreeview` does not provide native AccessKit TreeItem semantics in this version. The app retains its hierarchy/expansion layout while exposing named, focusable egui row buttons and adapting arrow-key navigation through the same guarded selection path. This is not a claim of complete screen-reader qualification; Narrator remains unopened as requested.

## Compatibility and offline constraint

ProcessCraft pins egui/eframe 0.37.0 and patches crates.io egui and its shared types to StoryTold revision `6d518fc`; craft-ui is pinned to `acc262e`. A third-party crate requiring `egui ^0.37` can resolve to that patched version, but that is only a version-level match: a clean compile and behavior/accessibility checks against this exact fork remain necessary. A crate requiring `^0.36` instead resolves a separate incompatible egui type universe; the patch cannot make 0.37 satisfy ^0.36. Optional native integrations and transitive dependencies also need review.

Offline use after building is distinct from an offline build. These UI components do not inherently require a network at runtime, but Cargo must already have every selected crate, transitive dependency and pinned Git revision cached or vendored. A local registry-source directory search found none of the candidate crate packages below; this is not a complete Cargo cache or offline resolution test. Do not promise an offline build until the actual locked dependency graph has been fetched/vendored and `cargo build --locked --offline` succeeds.

## Ranking

1. **Adopt existing APIs where needed:** `egui::ScrollArea::show_rows` renders the visible range of equal-height rows and needs no new crate; use it when library/dictionary/table size justifies virtualization. `show_viewport` enables custom variable-height culling but requires application-owned indexing. Native `Panel`, `MenuBar`, `CollapsingHeader`, `ViewportBuilder` and eframe viewports cover the current fixed shell, menus, simple tree and native windows. Keep the already-used `rfd` 0.15 file dialog for local file/folder picking and saving; its synchronous calls block while the dialog is open. [ScrollArea](https://docs.rs/egui/0.37.0/egui/containers/scroll_area/struct.ScrollArea.html), [panels](https://docs.rs/crate/egui/0.37.0/source/src/containers/panel.rs), [viewports](https://docs.rs/crate/egui/0.37.0/source/src/viewport.rs), [rfd FileDialog 0.15.4](https://docs.rs/rfd/0.15.4/rfd/struct.FileDialog.html).
2. **Evaluate `egui_extras` 0.37.0 for a real table need.** `TableBuilder` offers fixed headers, resizable/clipped columns and scrolling; `TableBody::rows` supports efficient equal-height rows. Its declared egui requirement is ^0.37.0. Prefer the small table feature set; do not enable image/SVG loaders merely for tables. Verify fork compile, keyboard/accessibility and actual row behavior first. [crate and dependencies](https://docs.rs/crate/egui_extras/0.37.0), [TableBuilder](https://docs.rs/egui_extras/0.37.0/egui_extras/struct.TableBuilder.html), [TableBody](https://docs.rs/egui_extras/0.37.0/egui_extras/struct.TableBody.html).
3. **Evaluate `egui_ltreeview` 0.10.0 only for a richer project tree.** `TreeView::new(...).show(...)` supports directories/leaves, keyboard navigation, multi-selection and drag/drop actions. It requires egui ^0.37. The existing shallow navigation does not justify adopting it until those behaviors are needed; map its actions onto existing document IDs and draft guards. [crate and API](https://docs.rs/crate/egui_ltreeview/0.10.0).
4. **Defer `egui_tiles` 0.18.0.** It requires egui ^0.37 and offers tabs, split/grid layouts and draggable docking via a `Behavior`; evaluate only if user-configurable docking becomes a product requirement. The approved fixed workbench does not require its state model. [crate](https://docs.rs/crate/egui_tiles/0.18.0).
5. **Defer `egui_flex` 0.9.0 and `egui_taffy` 0.16.** Both target egui 0.37; taffy adds an external layout engine and lists MSRV 1.95 (workspace is 1.98.1). Flex provides grow/wrap, while taffy provides grid/flex/block. Neither fixes the core functionality of this fixed desktop shell; consider a targeted prototype only for a demonstrated layout gap. [egui_flex manifest](https://docs.rs/crate/egui_flex/0.9.0/source/Cargo.toml), [egui_taffy compatibility](https://github.com/PPakalns/egui_taffy#version-compatibility).
6. **Do not adopt `egui_dock` 0.21.1 now.** It has mature `DockState`, `DockArea` and `TabViewer` APIs, but its published dependency is egui ^0.36, incompatible with the current 0.37 types. Even with a future compatible release, docking is unnecessary for the approved shell. [crate dependencies](https://docs.rs/crate/egui_dock/0.21.1), [API](https://docs.rs/egui_dock/0.21.1/egui_dock/).

The ranking above records the original research decision. Two candidates were subsequently integrated at the user's explicit request, as recorded above; the deferred candidates remain unused. New dependencies still require a single egui type graph, compile checks against the pinned fork, a locked offline build and keyboard/high-DPI checks.
