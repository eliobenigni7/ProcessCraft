# M3.0: Deterministic diagram auto-layout

**Status:** Implemented as a bounded, opt-in profile; qualification is limited to the fixtures and environments recorded in [M3 evidence](../implementation/m3-evidence.md). Preview, cancellation, guarded apply and undo/redo exist. A 400-node chain was accepted while a more complex 400-node/500-edge case was safely refused; routing has explicit obstacle and work budgets. Proposals are best-effort: only overlapping nodes, invalid geometry, unroutable edges and the budgets refuse; crossings, shared channels and label or route overlaps are returned as counted `warnings` with `metrics`, superseding the collision-free requirement below. The node scope is now every flow node except annotations, data references, boundary or attached events and expanded subprocesses. This document retains the original design and acceptance goals for continuing qualification, not a claim that every goal or BPMN structure is supported.

## Contract and scope

Layout one explicitly identified document and diagram. Never run on import, open, recovery, save, export or a background event. The first implementation supports a flat BPMN process with sequence-flow branches, joins and cycles, at most one pool and non-nested lanes, and the already-supported task, event and gateway shapes. Preserve the original flow graph, IDs, node kinds, conditions, names, documentation, lane memberships, other diagrams, styles, resources, dictionary references, provenance and all foreign data. Never linearize branches. Refuse preserved-source and retained-extension capabilities, multiple pools, nested lanes, collaboration/message flows, associations, annotations/data objects, ambiguous/missing/duplicate DI mappings or any unsupported structure, with a specific diagnostic and no partial result. Expand scope only with explicit preservation tests.

Preview returns a transient proposal and diagnostics, without changing content, dirty state, history or generation. Apply and Cancel are explicit. Preview must show all proposed shapes, connectors and labels, identify the document/diagram, and indicate unsupported or failed proposals; Cancel discards it. Apply rechecks originating session ID, generation, document/diagram identity and editable capability in the command boundary. Reject stale proposals rather than recomputing or applying to another session. A proposal equal to current geometry is a no-op: no history entry, dirty transition or generation change. Repeat layout after applying must produce identical geometry. Preserve manual changes unless the user explicitly applies a new layout.

## Algorithm and resource limits

Implement a small deterministic algorithm in `crates/processcraft-core/src/layout.rs` using standard library collections, not a new dependency. Sort all ties by stable XML ID, never hash iteration order. Preserve node sizes and existing pool/lane ordering; use fixed spacing and a fixed origin (0, 0). Collapse strongly connected components for ranking, assign layers on the resulting DAG by longest path, order nodes stably within each layer and lane, and place cyclic members in stable order. Size pool and lanes to contain placed shapes; place unlaned nodes in a separate band without changing membership. Route each sequence flow orthogonally between shape borders using deterministic reserved channels, including self-loops and back edges. Place existing external shape labels by translating with their shapes; place existing edge labels at a deterministic non-overlapping route segment, retaining size and style. If a collision-free supported result cannot be constructed within the limits, return a diagnostic and do not apply; never hide a failed route or overwrite semantic data. Define tie-breaks, margins and coordinate rounding as constants and test them. No randomness, system fonts, clock, machine-specific measurements or network services participate.

Bound inputs to at most 400 shapes and 500 edges per diagram, 64 lanes, 16 waypoints per edge and 1,000 geometry operations; cap coordinates to the existing validator's finite valid range. Reject larger or malformed input before work. Bound route-search work by a fixed operation budget; check an explicit cancellation token between ranking, placement and route steps. Run desktop computation off the UI thread, expose Cancel, and return a bounded-work/cancelled diagnostic with no proposal on exhaustion. Establish a 2-second target for the maximum supported fixture on the documented qualification machine; a deadline or budget failure leaves the project unchanged. Tests must not depend on wall-clock timing. If the algorithm cannot meet the target, reduce the documented ceiling or optimize with evidence, not unbounded search.

## Implementation checkpoints

1. **Pure proposal and validation.** Add `layout.rs` and export it through `crates/processcraft-core/src/lib.rs`. Define bounded input validation, cancellation/budget, deterministic proposal containing session ID, generation, document ID, diagram ID, original and proposed geometry, and structured diagnostics. Snapshot from `Session::snapshot()` in `commands.rs`; do not mutate it. Verify all shapes and edges map uniquely to supported semantics. Ensure external labels and typed styles are represented in the proposal, including unchanged label styles. Use focused tests in `crates/processcraft-core/tests/layout.rs`.
2. **Atomic geometry application.** Existing `Mutation::MoveShape` translates shape labels, `Mutation::Reroute` only changes edge waypoints, and `Request::Batch` has a 1,000-mutation limit. Add a dedicated bounded geometry mutation in `commands.rs` for exact shape bounds, edge waypoints and optional label bounds, preserving styles and all other fields. Validate unique IDs, finite coordinates, diagram membership and `Capability::Editable` explicitly: existing geometry mutations use the less restrictive `doc(..., false)`, so they alone do not enforce this contract. Dispatch through `Session` with expected generation and an explicit session-ID check; one complete validated mutation yields one history entry with exact undo/redo. Do not split a layout across batches. Extend core history/validation only as needed. A geometry-only mutation must not change the persisted project schema, required capabilities, native reader/writer, resource bytes or checkpoint representation; if this cannot hold, stop and amend the plan before implementation.
3. **Desktop.** Add a bounded worker alongside `apps/processcraft/src/jobs.rs`; wire the existing shell/model menu and `app_canvas.rs` to explicit Preview, Apply and Cancel. Render the proposed geometry as a separate transient scene using `processcraft-render`, keeping the current project authoritative. Commit or resolve outstanding drafts before snapshot. Disable Apply while work runs, after session/generation change, or after cancellation; report a precise error and allow retry. Close/new/open must cancel or safely discard late results by session/generation identity; no stale worker result may replace a newer preview. Keyboard access, light/dark and 200% layout must remain usable. Do not expose fabricated success states.
4. **CLI and MCP parity.** Add explicit preview/apply commands to `apps/processcraft-cli/src/{args,run,mcp}.rs` and update descriptors/schemas. All invoke the same core proposal and atomic apply; no transport-specific layout implementation. Preview includes proposed geometry and base identity in structured output. Apply requires that exact proposal and expected identity, not an implicit fresh computation. For attached MCP, enforce existing session, request deduplication and authorization/grant rules; stale/replayed calls must not mutate. For file-based CLI, use the existing bounded open/staged save and explicit output path, never replace an input implicitly. Cancel/invalid/stale exits nonzero and leaves files unchanged. Add transport-specific integration tests and help examples with actual implemented flags when completing the work.
5. **Integration and evidence.** Document supported/refused constructs and exact limits in user/CLI help. Preserve canonical project content except intended geometry; verify native and BPMN round trips and undo/redo. Record measured maximum-fixture duration and machine separately from correctness. No compatibility or accessibility qualification is implied by this plan.

## Required tests and acceptance

- Deterministic geometry for a linear flow, parallel branches and joins, multiple lanes in one pool, loop, self-loop, disconnected nodes and long labels. Assert border endpoints, orthogonal segments, lane containment, no node overlap, preserved branches and readable external labels. An impossible collision case must refuse safely rather than fabricate success.
- Repeated preview and preview after apply return identical geometry; applying identical geometry is a true no-op. Preview/cancel leaves generation, dirty state, history and serialized project unchanged. Undo and redo restore exact geometry, external label positions and styles in one step.
- Refuse retained extensions, preserved source, missing/duplicate DI, multiple pools, nested lanes, unsupported elements, invalid coordinates and limits; ensure no geometry, semantic content, file or history changes on any failure, cancellation or exhausted work budget.
- Change a draft/session/generation or close/reopen between preview and apply; reject stale proposal for GUI, CLI and MCP. Exercise duplicate/replayed attached requests and concurrent mutation without applying twice.
- Compare semantic fields, IDs, conditions, membership, styles, resources and unrelated diagrams before/after; native save/reopen and BPMN export/reimport preserve all qualified content. Include checkpoints/references if they exist when this slice is executed; no current checkpoint feature is assumed.
- Run `cargo test -p processcraft-core --test layout`, the affected desktop and CLI/MCP tests, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace`. Run native GUI Preview/Apply/Cancel and stale-result checks in both themes and at 200% without launching Narrator. Record failures and qualification limits honestly.
